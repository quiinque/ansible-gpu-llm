# Результаты проверки исходной версии

Дата: 24 ноября 2026.

## Стенд

Windows 11 → WSL2 → Ubuntu 24.04 → Docker → Ollama. GPU: RTX 3070 8 ГБ; RAM хоста 32 ГБ. WSL: лимит RAM 24 ГБ, swap 8 ГБ. Модель qwen3.6:27b, контекст 2048, thinking отключён в smoke test.

Команды выполнял пользователь на своём компьютере. Ниже зафиксированы предоставленные PLAY RECAP и ответ API; полные логи и digest образа не приложены. Это не независимый повторный прогон автора документации.

## Фактические результаты Qwen3.6-27B

| Проверка | PLAY RECAP |
| --- | --- |
| Развёртывание профиля | ok=25 changed=2 unreachable=0 failed=0 skipped=3 rescued=0 ignored=0 |
| Повторное развёртывание | ok=25 changed=0 unreachable=0 failed=0 skipped=3 rescued=0 ignored=0 |
| verify.yml после wsl --shutdown и повторного запуска Ubuntu | ok=5 changed=0 unreachable=0 failed=0 skipped=0 rescued=0 ignored=0 |

Проверка verify.yml включает генерацию, непустой response, done=true, eval_count>0 и size_vram>0 у целевой модели. Последнее подтверждает выделение GPU-памяти, но не полное размещение на GPU. Логи содержали буферы CPU и CUDA0.

Повторный запуск подтверждает идемпотентность на данном стенде. Переход на большую модель выполнялся на уже настроенном узле; веса предварительно скачали командой ollama pull. Это не тест установки 27B с чистой ОС одним запуском.

## Ручной запрос API

Запрос: объяснить назначение Ansible в трёх предложениях. Параметры: stream=false, think=false, num_ctx=2048, num_predict=128.

Модель вернула связный ответ, done=true, done_reason=stop. Полученные метрики:

- total_duration: 74560961598 нс, около 74,6 с;
- prompt_eval_duration: 51065971000 нс, около 51,1 с;
- eval_count: 91;
- eval_duration: 22275238000 нс, около 22,3 с;
- скорость генерации: 91 / 22,275238 ≈ 4,1 токена/с.

Это один запрос без нагрузочного тестирования. Скорость генерации не включает обработку входного текста. Для localhost в curl использован --noproxy '*': ранее запрос без обхода прокси вернул HTTP 503. Точный источник 503 отдельно не исследовался.

## Ограничения

- В WSL используется драйвер Windows. Ветка установки Linux-драйвера, headers, Secure Boot/MOK и reboot физического Ubuntu Server не проверялась.
- Проверено восстановление после запуска WSL; автоматический старт WSL при загрузке Windows не настраивался.
- Внешняя недоступность порта отдельно не проверена; Compose публикует его только на 127.0.0.1.
- Нагрузочные тесты, резервное восстановление и мониторинг не выполнялись.
- Mutable image/model tags и диапазон версии коллекции не обеспечивают строгую воспроизводимость. Перед production зафиксируйте проверенные версии и digest.
- Результаты отдельного ansible-lint не предоставлены. На этапе подготовки публичного пакета выполнен просмотр всех файлов и проверка структуры. Эта формулировка относилась к исходной версии f7986fa. В текущей ветке выполнен рефакторинг роли; он требует отдельной приёмки.

## Соответствие заданию

Playbook содержит настройку драйвера, Docker CE и NVIDIA Container Toolkit; развёртывание Ollama; загрузку модели; systemd enable и restart policy; healthcheck; API smoke test и проверку VRAM. README содержит серверный запуск, SSH-туннель, пример API, диагностику и предложения по архитектуре, защите API и мониторингу. Сценарий WSL выделен в WSL-TEST.md. Для production необходима серверная приёмка по README.

## Рефакторинг роли

Результаты выше относятся к commit f7986fa до выделения роли. Ветка refactor/ansible-role меняет структуру, имена переменных, выбор image и driver, reboot policy, зависимости и тесты. Старые GPU-результаты нельзя считать подтверждением новой реализации. CI проверяет YAML, ansible-lint и синтаксис; аппаратную приёмку новой роли нужно повторить по WSL-TEST.md и на Ubuntu Server.

Локально после рефакторинга: 18 YAML/config файлов разобраны js-yaml 4.1.1 без ошибок, git diff --check пройден. Ansible-lint, syntax-check и Compose render test настроены в CI, но их успешный запуск ещё не подтверждён. GPU-прогон новой роли не выполнен.
